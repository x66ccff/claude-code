# 构建与部署

## 从源码运行

安装项目要求的 Bun 版本，在仓库根目录执行：

```bash
bun install --frozen-lockfile
bun run typecheck
bun run build
bun dist/cli-bun.js --version
bun dist/cli-bun.js
```

开发调试可使用 `bun run dev`。修改源码后，重新构建才能更新构建产物。
请以当前构建脚本的产物和启动方式为准。

## 配置

首次启动后使用 `/login` 配置供应商，或按供应商文档设置环境变量。
仓库中的 `.env.example` 只列出可选变量；Bun 可读取未跟踪的 `.env`，
其他启动方式应显式加载环境变量。仅为需要的供应商提供凭据。

配置文件、凭据、日志、会话、学习档案及个人插件保存在本机。
需要自定义路径时，使用启动参数或环境变量，避免将用户目录写入源码。

## 容器与持久化目录

在容器或云工作站中，将源码、构建产物和缓存放在管理员指定的持久卷。
通过 `BUN_INSTALL_CACHE_DIR` 指定缓存目录；路径由部署环境提供。
检查目录权限和已有产物后再安装或重建，避免无条件清理依赖或用户配置。

## 分发

- 为目标操作系统和架构构建并验证原生依赖。
- 只打包程序需要的构建产物、原生依赖和通用安装说明。
- 不打包 `.env`、Claude 设置、凭据文件、个人运行记录或已认证的浏览器数据。
- 在目标机器配置供应商与凭据，并验证 `--version`、`--help` 和实际启动。
- 升级时保留目标机器的用户配置，避免用打包机器的配置覆盖。

公开源码维护流程见 [public-repository-maintenance.md](public-repository-maintenance.md)。
